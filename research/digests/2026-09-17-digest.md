## Chinese-community findings

**SenseNova U1.5's prompt dialect is no longer unresearched — the corpus's #1 open target is closed.**
The vendor's own `src/sensenova_u1_5/image_pe.py` served **live** (zero cache staleness) and contains
`IMAGE_PE_SYSTEM_PROMPT` verbatim `[OFFICIAL]`. Highlights:

- **U1.5 has a negative channel and the vendor sizes it:** `"negative": "two to four likely visual
  failure classes"` — a **field inside the prompt JSON**, not a CLI flag, capped at 2–4 and framed as
  *failure classes*, not banned objects. Contrast the SDXL-era 50-token list.
- **A hard length target: 1,100–1,500 output tokens** for ordinary requests; a five-row immutable 2K
  canvas whitelist; and `visible_copy`, an **exhaustive ledger of intended glyphs** preserved
  character-for-character with *"Never add pseudo-text, labels, numbers, logos, credits, signatures,
  watermarks, or metadata."*
- **Multi-reference IS indexed** — 「第一张图」 / `Image-1` / `Image 1`, **three orthographies in one
  vendor doc**. Bounding boxes are *drawn on the image* and must be **explicitly ordered erased**.
- **`quality_tags` is a live first-party schema field**, 9–10 Chinese items per gallery prompt
  (`['高清街拍','自然光','高细节','真实生活方式摄影','暖调午后','胶片颗粒', …]`).
- ⚠ **SenseTime ships TWO incompatible Render-JSON schemas** — 11 keys vs 17, sharing only
  `canvas`/`lighting`/`style`, **disagreeing on the negative field** (2–4 failure classes vs arrays of
  25–45 terms). Both `[OFFICIAL]`, neither acknowledges the other. **Don't present either as "the" schema.**
- **A rewriter-ethics pair worth teaching on its own:** Wan 2.2's rewriter silently substitutes content
  and recolours skies without telling the user (「而不要拒答或者提醒用户」); SenseTime's forbids invention
  outright — *"never invent brands, identities, contacts, certifications, prices, dates, statistics,
  rankings, quotations, or factual claims."* Same country, same year, opposite answers.

**Wan 2.2 `generate.py` read fresh** `[OFFICIAL]`: **`tar_lang="zh"` is confirmed first-party** (grade
upgrade from `[LORE-transcription]`), `magic_prompt` is unimported, and a **new gotcha** — the prompt
extender **fails silently back to the original prompt**, and it is **seeded**.

**Flagged as SEO artefact, not evidence:** a widely-syndicated Chinese claim that U1.5's 4K path is
triggered by naming 「4K」/「高分辨率」 keywords. No SenseTime surface says this, and the documented

## Contradicts our current guidance

1. 🔴 **Retract the LTX text-encoder quarantine.** The 09-13 flag rested on one user; **the same account
   posted the opposite eight days earlier** — 2026-08-17: *"After the text encoder change there is some
   improvement in permanence / prompt-following!"*; 2026-08-25: *"They uploaded an entire wrong
   checkpoint…"*; and the same day, that the defect occurs *"both with the old and with the new text
   encoders."* Downgrade to `[LORE — single user, self-contradicting]`. **Keep** the corroborated fact
   that an undocumented re-upload happened, and the narrow guidance: **record which
   `gemma4-12b-with-proj-ltx-2.5-*.safetensors` you ran**, because Lightricks replaced it in place.
2. 🔴 **`DEFAULT_NEGATIVE_PROMPT` is on the DISTILLED path, not the 30-step one — and that is worse.**
   The vendor's own card imports `DISTILLED_SIGMA_VALUES` and passes `negative_prompt=DEFAULT_NEGATIVE_PROMPT`
   alongside `guidance_scale=1.0, stg_scale=0.0`. **Lightricks' flagship reference code ships an inert
   negative prompt.** The false affordance is not a ComfyUI packaging bug — it is in vendor code.
3. 🟠 **"Single-paragraph packaging does not survive" was overstated.** The vendor guide makes a **single
   flowing paragraph of 4–8 sentences the default** and licenses screenplay style as the exception for
   dialogue/multi-beat. `art-alex`'s line-per-beat rewrite was the vendor **applying its own documented
   exception**, not contradicting its guide. **Teach the conditional, not either absolute** — and take
   the number the corpus never had: **4–8 sentences**.
4. 🔴 **"H3 has two variants, not five" is contradicted by MiniMax's own skill**, which names and defines
   **T2VA, I2VA, FL2VA, L2VA, Ref2VA**. Both sources first-party; keep both, and say *"five documented
   input modes; one Chinese vendor page enumerates only two reference variants."*
5. 🔴 **"Quality-suffix tags are retired" is flatly false for U1.5** — `quality_tags` is a first-party
   schema field. Amend to: **generic boosters are retired; a short medium/texture tag array is
   first-party for U1.5.** (This supersedes the softer 09-13 Z-Image-Turbo scoping.)
6. 🟠 **"Prose, not tags" now needs a third category: schema.** Two Chinese vendors ship first-party
   *structured* prompt formats (SenseTime's Render JSON, MiniMax's named-field H3 schema). This is
   strong support for the 09-13 line that **the training recipe, not the encoder class, sets prompt
   style** — and it means the rule must read *"prose, not tags — but some models want a schema."*
7. 🟠 **The IC-LoRA "no trigger, no special shape" rule does not generalise.** The dialogue IC-LoRA has a
   **mandatory template** — `[Speaker] is speaking [Language/Accent], saying: "[Dialogue]"` — with hard
   requirements (full dialogue text, native script, single speaker, five validated languages, and a
   syllable-timing rule). **Teach per-adapter, never per-family.**
8. 🟢 **"CFG≈1 ⇒ negatives inert" — strengthened twice, and bounded.** Vendor text now says *"Fixed
   8-step schedule, CFG=1"*; U1.5's 8-step LoRA ships `--cfg_scale 1.0`. But U1.5's **base** path has a
   live `cfg_scale`. So it is a **per-path rule, not a per-model one**: *check the guidance value on the
   path you are running, not the model you downloaded.*
9. 🟢 **Priority-1 negative result: both `art-alex` `[STAFF]` claims survive the 09-10 card edit.** The
   revised Pixel-Spatial-Upscaler card has **no trigger section of any kind** and the vendor CLI passes
   `--prompt "your prompt here"`, so *"needs no trigger phrase"* is now `[STAFF]` **+ `[OFFICIAL]`**; the
   card is silent on prompt content, so *"use the source video's own prompt"* is untouched. (They are
   `staff-claims-2026-09.md` **row 4**, not row 5 — citation erratum.)

## Errata — corrections to the 2026-09-13 digest and to standing tooling rules

1. **Quarantine flag → retracted** (Contradicts #1).
2. **`DEFAULT_NEGATIVE_PROMPT` scoping → inverted** (Contradicts #2).
3. **"Single-paragraph packaging does not survive" → overstated** (Contradicts #3).
4. **"H3 has two variants, not five" → wrong** (Contradicts #4).
5. **"Paste the URL verbatim into the instruction to defeat the provenance gate" → does not work.** The
   gate mints URLs only from a **WebSearch Links array**; a URL pasted into an agent brief is still
   refused. This was the 09-13 digest's #1 next-run recommendation and it is falsified.
6. **Gated-HF access, corrected:** `…/raw/main/<file>` and `…/commits/…` return **empty** on gated LTX
   repos, but **`…/blob/main/<file>` renders the whole card**, no SHA and no login. **Blob first;
   commit-pinned raw is the fallback, not the primary** — this reverses 09-10 errata 3's emphasis.
   It is how two gated LTX cards were read this run.
7. **"GitHub HTML is stale" → mis-attributed.** The staleness is the **fetch tool's per-URL response
   cache**, its age is **0–46 days and varies per URL**, and it is **exactly measurable** from
   `meta-request-id`. Rule 7 and the 09-10 errata should read: *date every GitHub read from
   `meta-request-id` and treat the page as a snapshot of that date.* This retro-explains the 09-10
   "~10 weeks stale" observation without positing a GitHub outage. **Agent A published one
   `[SYNTHESIS]` from a 46-day-old snapshot and retracted it in-file (§7.5) — the method caught it.**
8. **HF dates are now exact.** HF comment anchors are **MongoDB ObjectIds**: `int(anchor[:8], 16)` gives
   UTC. Validated against three known corpus dates, all matched. This **kills the 09-10 errata 4
   "HF surfaces disagree about dates"** problem for discussion comments.
