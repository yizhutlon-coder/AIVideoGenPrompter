## Official guide changes

1. **The LTX-2.5 prompting guide was rewritten and the ≤150-word cap is gone.** `[OFFICIAL]` (#12,
   CONFIRMED across the whole page). Current guidance verbatim: *"Aim for roughly **4–8 descriptive
   sentences**"* and, under Length, *"Match length to complexity. A simple single shot is often 4–8
   sentences; a longer screenplay-style scene can run longer, provided every sentence adds concrete
   visual or audio detail."* **There is no word count anywhere on that page.** The only surviving word
   figures are the LTX-2 GitHub README's *"Keep within 200 words"* and the ≤150 that lives **only** in
   the legacy **LTXV-0.9** enhancer node (`prompt_enhancer_nodes.py`, `unsloth/Llama-3.2-3B-Instruct` +
   `MiaoshouAI/Florence-2-large-PromptGen-v2.0`, `max_resulting_tokens` 256/512) — a component 2.5 does
   not use. `ltx23.md` items 1 and 6, §*Contradicts* #3/#4.

2. **LTX-2.5 has a documented Multi-Shot prose syntax, and it gates rather than repeals the "no cuts"
   rule.** `[OFFICIAL]` (#13, byte-for-byte). Write the scene as **one chronological paragraph**; do not
   use a shot list, numbered beats or sluglines *unless you also name the cut in prose*. At every cut:
   **name the transition**, **re-establish the new shot**, **keep identity consistent**, **state audio
   continuity**. Tips: **prefer 2–4 shots**; give each shot a clear job; keep action chronological. The
   current Gemma enhancer system prompt still says *"DO NOT use timestamps or describe scene cuts unless
   explicitly requested"* — so cuts are legal only when the author names them, and the enhancer will
   neither invent nor remove them. `ltx23.md` item 3.

3. **Auto Duration is a separate optional weight file and is NOT wired into the shipped ComfyUI
   template.** `[OFFICIAL]` + `[TESTED]` static inspection (#17: the substantive half CONFIRMED — no
   duration-head loader, no `model_patches` reference). The template exposes `duration` as a plain
   `PrimitiveInt` = 5 seconds, `"fixed"`. The prediction requires
   `ltx-2.5-duration-head-bf16.safetensors` on the Python path (`--duration-head-path`, or
   `num_frames=None` in the Diffusers modular recipe). Comfy Org's Rob calls it *"a small experimental
   duration head model"*. **In ComfyUI today, duration is a number you type.** `ltx23.md` item 12.

4. **LTX-2.5's official mechanics, verbatim.** `[OFFICIAL]` `pytorch-api.md`: *"Width and height must be
   divisible by 32. Frame count must follow the pattern `8n + 1`"*; `ltx-core/README.md` gives the
   reason — the VAE compresses 8× temporally and 32× spatially, so `(F-1) % 8 == 0`. DubIt and Retake
   **silently snap** frames to the nearest `8k+1` rather than erroring. Sampling: distilled 4–8 steps at
   CFG 1.0; full model 20–50 steps at CFG 2.0–5.0 ("Recommended 3.0–3.5"). The 20 s ceiling is an
   API/product figure, not a local one. The Gemma 4 encoder is **version-gated** (`gemma4-12b-ltx-v1`)
   and stock Gemma 4 is explicitly not a substitute. `ltx23.md` item 8, 9.

5. **LTX-2.5's IC-LoRA roster changed and two names the app teaches are wrong.** `[OFFICIAL]`
   **Union Control** is now the pose route (*"depth, canny, and pose in one checkpoint"*); the
   standalone `ltx-2-19b-ic-lora-pose-control` is an LTX-**2.0** file absent from the 2.5 table.
   "Motion Track Control" is documented as **Motion Control**, with two dedicated nodes (**LTX Draw
   Tracks**, **LTX Sparse Track Editor**) and a "3–4 keypoints per track" recommendation. Prompt rules

   for adapters that have one (`DEBLUR`, `REMOVEBEARD`, `COLORIZE`, `ADD WATER`, `ENHANCE QUALITY`);

   plus optional masks). **HDR, Dub-It and Relight are LTX-2.3-only** — *"LTX-2.5 support in
   development"*. `ltx23.md` item 13, §*Contradicts* #6.
