### 1.1 VDN-MiniMax-H3 (VDN-H3) — open weights, 2026-09-07 [OFFICIAL, relayed]

`https://modelscope.csdn.net/6a9e22e148977663a5dd89fd.html` (published 2026-09-07, accessed 2026-09-13)
Weights: `https://modelscope.cn/models/OpenVDN/vdn-minimax-h3` · code `https://github.com/OpenVDN/vdn-minimax-h3`

> OpenVDN 团队开源 VDN-Minimax-H3（VDN-H3），同时公开模型权重、训练代码与优化后的推理实现。该工作基于
> MiniMax-H3，将局部 Softmax 注意力与按帧更新的线性注意力结合，再通过少步蒸馏降低视频生成开销。

*(gloss: OpenVDN open-sources VDN-H3 — weights, training code and an optimised inference stack.
Built on MiniMax-H3; combines local softmax attention with per-frame linear attention, then uses
**few-step distillation** to cut generation cost.)*

Facts that matter for our corpus:
- **Corroborates "H3 local = 768p".** Every official benchmark quoted is 768p; no local 2K anywhere.
  `[OFFICIAL, relayed]`
- **Corroborates the 17n+5 frame grid and 「最长 15 秒」.** The headline clip is `约 14.4 秒、768p`.
  At 24 fps, 17·20+5 = **345 frames = 14.375 s ≈ 14.4 s** — exactly on the grid and just under the
  15 s ceiling. `[SPECULATION]` on the arithmetic, `[OFFICIAL, relayed]` on the 14.4 s / 768p figures.
- **The local text encoder is named:** `文本编码器不包含在上述 VDN-H3 权重包中` and, verbatim from the
  usage section:

  ```text
  自定义文本需要先通过 H3 使用的 Qwen3-VL-32B 文本编码器转成特征，再进入生成模型。
  ```

  *(gloss: "custom text must first be turned into features by the **Qwen3-VL-32B** text encoder that H3
  uses, before entering the generation model.")* Our `minimax-h3.md` does not record the local encoder
  identity. This is directly load-bearing for the "write prose because the encoder is an LLM" debate:
  H3's local conditioning path is a **32B VLM**, and it is a separate download from the weights.
  `[OFFICIAL, relayed]`
- **Two-stage prompting is mandatory locally.** `encode_prompt.py --prompt "..." --out prompts/mine.pt`
  then `infer.py ... render.prompt_file=prompts/mine.pt`. Prompts are pre-encoded to `.pt`; the repo
  even ships `prompts/example_2.pt`. A student cannot type a prompt into the sampler directly.
- `[SPECULATION]` **Licence tension worth watching.** VDN-H3 is a *distilled* derivative
  (`少步蒸馏`) redistributed under the MiniMax H3 Community Licence, while that licence carries a
  no-distillation clause. I did not retrieve the VDN-H3 `LICENSE` file itself this run, so this is
  flagged as an open question for Agent B / next sweep, not as a finding.

### 1.2 H3-World — open weights (LoRA), 2026-09-09 [OFFICIAL, relayed]

`https://modelscope.csdn.net/6aa0bd3048977663a5de1953.html` (published 2026-09-09, accessed 2026-09-13)
Weights `https://modelscope.cn/models/DANNY621/H3-World` · code `https://github.com/Danzer1xxxxChan/H3-World`
· report `https://modelscope.cn/papers/2609.01560`

This is the **most prompt-relevant release in the window** and it lands directly on a corpus position.

> 该工作将视频模型已有的语言动作理解用于控制，通过轻量微调，只用 8k 条数据和 0.199% 的可训练参数

> H3-World 将角色与相机动作转换为文本指令，沿用 MiniMax-H3 预训练的文本处理路径，并通过定向注意力将
> 指令与对应的视频潜变量区间对齐。

*(gloss: it repurposes the video model's **existing language-based action understanding** for control;
character and camera actions are converted into **text instructions** carried on H3's pretrained text
path, aligned to specific latent-frame intervals by directed attention. 8k samples, 0.199% trainable
params, rank-32 LoRA, 10,000 steps.)*

And the claim that matters most:

> 官方表示，未经动作控制训练的 MiniMax-H3，已经能够根据文字生成大致符合要求的角色和相机运动。

*(gloss: "the authors state that MiniMax-H3 **without any action-control training** can already produce
roughly correct character and camera motion from text alone.")* `[OFFICIAL, relayed]`

Further load-bearing details:
- The ablation compares three action-conditioning routes — additive key-embedding bias, FiLM, and
  H3-World's **text** interface. Reported result: the first two gave `较弱或不一致的动作响应`
  (weak or inconsistent motion response); the text route gave coordinated motion. The authors' own
  conclusion, verbatim: `这一结果说明可以通过 H3 已有的文本路径传递动作条件。`
  `[TESTED — partial methodology]`: the comparison is stated as run on a **held-out video with the same
  recorded action sequence**, and the demo grid is `固定首帧、随机种子和采样配置` (fixed first frame,
  fixed seed, fixed sampling config, varying only the control instruction). Seeds/config are declared
  as controlled but **not enumerated**, and no grid of numeric scores is reproduced in this article —
  so this is graded as tested-with-partial-methodology, not full `[TESTED]`.
- Action vocabulary: 9 character instruction classes × 16 camera classes, **135 legal combinations**,
  of which the training set covers **83**; the remaining **52 were never seen** and the paper claims
  compositional generalisation to them. `[OFFICIAL, relayed]`
- Key-to-language mapping lives in `code/abot/action_script.py` — a concrete, harvestable
  natural-language camera/character phrasebook. Not yet retrieved (see §6).
- **Reference invocation, verbatim from the official example:**

  ```text
  python3 code/abot/infer.py --checkpoint checkpoints/H3-World/step-10000.safetensors \
    --first-frame examples/first_frame.png \
    --scene-prompt "A man in a yellow floral shirt stands in a dim, multi-level concrete parking garage." \
    --action-preset forward --seed 2 --steps 50 --num-frames 124 --cfg-scale 1.0
  ```

  Three things to note: output is `832 × 480、124 帧、24 fps，时长约 5.2 秒`; **124 = 17·7 + 5**, a second
  independent confirmation of the 17n+5 grid at a completely different duration; and `--cfg-scale 1.0`,
  meaning **negatives are inert in this configuration** — the same structural argument our corpus already
  makes for LTX distilled models now applies to this H3 derivative. `[OFFICIAL, relayed]`
- Note the prompt is **split into two fields**: a static `--scene-prompt` and a separate temporal
  `--action-preset`. That is an architectural separation of "what is in the scene" from "what moves",
  which our corpus currently teaches only as a *stylistic* discipline for I2V.

#### Discrepancies with the corpus (precise)

**D1 — "8 axes" is wrong as stated. The file names TEN axes in prose but enumerates only EIGHT.**
The ZH instruction sentence is verbatim:

```text
从下列电影美学设定中选择部分合适的时间、光源、光线强度、光线角度、对比度、饱和度、色调、拍摄角度、镜头大小、构图的电影设定细节
```

*(gloss: "select suitable details of time, light source, light intensity, light angle, **contrast**,
**saturation**, colour tone, shooting angle, shot size, composition")*

`对比度` (contrast) and `饱和度` (saturation) are named in the prose list but are given **no value
enumeration** below it. So: **10 named, 8 enumerated.** Our corpus's 8-axis list is the *enumerated*
set and is correct as a list of controlled vocabularies — but it should be relabelled, because a
student reading the rewriter prompt will see contrast and saturation mentioned as licensed dimensions.

**D2 — the prose list says `镜头大小`, the enumerated header says `镜头尺寸`.** The file is internally
inconsistent on this term. Our corpus records only `镜头尺寸`.

**D3 — ZH and EN rewriters are NOT parallel: the EN one caps the number of axes, the ZH one does not.**
- ZH: `可以任选，不必每项都有` — "choose freely, not every item is required". **No numeric cap.**
- EN: `选择不超过4种合适的...` — "select **no more than 4**". **Hard cap of 4.**

This is a substantive behavioural difference between `--prompt_extend_target_lang zh` and `en` that the
corpus does not record. `[LORE-transcription of OFFICIAL], corroborated`

**D4 — axis ORDER differs between ZH and EN.** ZH enumerates
时间 → 光源 → 光线强度 → 光线角度 → 色调 → 镜头尺寸 → 拍摄角度 → 构图.
EN enumerates Time → Light source → Light intensity → **色调 (colours)** → **光线角度 (light angle)** →
Shot size → Shooting angle → Composition. Colour tone and light angle are **swapped**.

**D5 — two rules the corpus does not have at all.**
- `若prompt出现天空的描述，则改为湛蓝色的天空相关描述，避免曝光；` (rule 6) — *any* sky description is
  rewritten to "azure sky" to avoid blow-out. This explains why overcast/sunset skies asked for in a
  short T2V prompt can come back blue: **the rewriter did it, not the model.** Practical, teachable.
- `如果prompt没有特别说明则选白天 !` in ZH vs `如果prompt没有特别说明则选 Day time!!!` in EN, but ZH
  additionally prefixes `可以不选` ("may be omitted") for 时间. EN has no such escape. So the EN rewriter
  is **more likely to force daytime** than the ZH one.

**D6 — undocumented silent content-substitution rules (8/9/10).** The T2V system prompt instructs the
rewriter to **silently replace** the user's prompt with an unrelated "high-aesthetic" prompt rather than
refuse, for suspected sexual content (rule 8), bikini content → forced to beach/pool/seaside (rule 9),
and — stated explicitly — same-sex kissing / intimacy, which it directs to be replaced with a
**different, non-intimate action** (rule 10). Verbatim tail of rule 10:

```text
请将原prompt替换为不同动作（不能是亲吻和其他亲密动作）的高美感prompt，而不要拒答或者提醒用户。
```

*(gloss: "replace the original prompt with a high-aesthetic prompt using a different action (it must
not be kissing or other intimate actions), and do not refuse or warn the user.")*

Teaching-relevant because the substitution is **silent by design** (`而不要拒答或者提醒用户` — "do not
refuse or warn the user"), so a student can get a totally unrelated video with no error. Flagging
factually; it is also a documented disparate-treatment clause. Not in our corpus.

## 7. Access notes

Feeds next run's tooling rules. Two new rules, three confirmations, one correction.

### NEW RULE 1 — `web_fetch` enforces a URL **provenance set**, and this dominates everything else

A URL can only be fetched if it appeared in a **user message**, a **prior `web_fetch` result**, or a
**WebSearch result**. Constructing a URL by pattern — even an obviously correct one — fails with
`URL not in provenance set. … Retries will fail.` This, not any site-side wall, was the primary blocker
in this sweep. It cost the Wan 2.2 `system_prompt.py` blob (§3.1) and the entire MiniMax Feishu doc set
(§3.4).

Sub-findings, each learned the hard way:
- **Link extraction from fetched pages is unreliable.** GitHub's blob pages seeded their own links fine,
  but `design.minimaxi.com`'s Feishu links did **not** enter provenance despite appearing in the fetched
  body — they are rendered as label-fused markdown
  (`[版本更新查看 H3 的最新版本…](https://vrfi1sk8a0.feishu.cn/docx/WAT9…)`) and were skipped.
- **A URL quoted in a WebSearch *answer summary* does not count.** It must appear in the **result link
  list**. The Wan2.2 `system_prompt.py` URL was quoted in a search summary three times and still failed.
- **Delegating to a subagent does NOT launder provenance.** Tested explicitly: the subagent hit the
  identical error. (It also reported that outbound **browser navigation is denied inside subagents** — its
  control fetch of `https://example.com` failed the same way. So subagents cannot be used as a fetch
  escape hatch at all.)
- **Practical workaround that works:** craft a WebSearch whose *result list* contains the exact URL —
  `allowed_domains` plus distinctive filename terms is the most reliable formulation. This is how the
  HF Krea and `Wan2.1/prompt_extend.py` URLs were obtained.
- **Best workaround of all:** have the instructor paste target URLs verbatim into the run instructions.
  URLs in the top-level task message are in provenance from the start.

### NEW RULE 2 — GitHub **blob** works, GitHub **tree** does not; HF is the mirror image

- `github.com/<org>/<repo>/blob/<ref>/<path>.py` returns **full source code**, cleanly.
  Verified on `https://github.com/Wan-Video/Wan2.2/blob/main/wan/text2video.py` and
  `https://github.com/Wan-Video/Wan2.1/blob/main/wan/utils/prompt_extend.py` (both 2026-09-13).
- `github.com/<org>/<repo>/tree/<ref>/<dir>` returns an **empty body** (JS-rendered file tree).
  Verified on `https://github.com/Wan-Video/Wan2.2/tree/main/wan`. **So you cannot browse to a file —
  you must already know its full path AND get it into provenance.**
- **Correction to an existing tooling rule.** The rule "HF blob pages render gated-repo cards" is true
  but is being over-generalised. HF blob pages render **markdown/model cards**; they return an **empty
  body for source-code files**. Verified on
  `https://huggingface.co/spaces/Wan-AI/Wan-2.2-5B/blob/ff5d8c78…/wan/utils/prompt_extend.py` (empty)
  versus `https://huggingface.co/krea/Krea-2-LoRA-vintagetarot` (full card, 2026-09-13).
  Suggested rewording: *HF blob view renders model cards and markdown, including for gated repos; it does
  NOT render source files — use the GitHub blob mirror for code.*
