## 2. New releases / license changes (Chinese-sourced)

### 2.1 MiniMax H3 open-weight licence excludes US / EU / UK / South Korea — `[OFFICIAL]`

This is the most consequential finding of the run and I did not see it in the corpus
positions listed in the brief.

Source: MiniMax's **own** Chinese-language H3 hub, `https://design.minimaxi.com/h3`
(accessed 2026-08-28), FAQ item "为什么我无法在欧盟 / 英国 / 美国 / 韩国下载模型权重？":

```text
开源权重许可目前暂不含欧盟、英国、美国与韩国——这些地区针对生成式视频（肖像、版权、
内容安全）的法规仍在演进。这是"暂时还不"，不是"永远不会"。当下两条路：API 全球可用
（内置安全措施）；受限地区的机构可申请正式授权做合规部署。
```

Additional licence terms from the same page, FAQ "我可以将 MiniMax H3 用于商业用途吗？":

```text
可以。社区许可授予免版税商用，三个要点：（1）商业产品/服务年收入超过 2,000 万美元
需另行书面授权（邮件 api@minimax.io，标题"MiniMax H3 licensing – authorization
request"）；（2）使用 H3 的商业产品须在界面显著标注"MiniMax H3"；（3）遵守《可接受使用
政策》，若你把 H3 托管给他人使用，须落实合理的内容安全措施。你生成的内容和你训练的衍生
模型归你所有。一个重要限制：产出与权重不得用于训练或改进其他（非 H3 系）AI 模型。
```

Four discrete constraints, all `[OFFICIAL]`:
1. **Territorial exclusion:** US, EU, UK, South Korea are outside the community licence for **weights**. The hosted API remains globally available.
2. **Revenue gate:** >US$20M annual revenue requires separate written authorisation.
3. **Attribution:** commercial products using H3 must visibly display "MiniMax H3" in the UI.
4. **No-distillation clause:** outputs and weights may not be used to train or improve any non-H3-family model.

**Stated reason — `[LORE]`, one step removed.** A Chinese-language X post claims
MiniMax DevRel lead Ryan attributed the regional carve-out to ongoing generative-video
copyright litigation with Hollywood studios:

> "MiniMax的开发者关系负责人 Ryan 表示，由于正在与多家好莱坞工作室进行生成视频版权
> 诉讼，所以不得不在H3的许可证加入了区域限制。"

Source: `https://x.com/MaxForAI/status/2084280158085845214` (surfaced via search
snippet; post body not independently fetched). I did **not** verify this against a
first-party MiniMax statement — the official page gives only the "regulations still
evolving" rationale. Treat the Hollywood-litigation reason as unconfirmed. Chinese
mainstream tech press covered the exclusion itself widely, e.g. Sina Tech
`https://finance.sina.com.cn/tech/roll/2026-08-03/doc-inikzzhi5905698.shtml` and
iFeng `https://tech.ifeng.com/c/8vIQbUpWpgr` (both headlined "国产大模型MiniMax H3
禁止美国人使用"), which corroborates the *fact* of the exclusion but not the reason.

**Relevance to Prompt Studio:** the app is a *prompt-translation teaching* tool, so it
probably never ships weights. But any doc that tells a US user "download H3 and run it
locally" is pointing them at a licence they are outside of. Worth a note in the app's
model guidance, and worth the digest editor's attention.

### 2.2 LTX-2.5 — Chinese-language release coverage, 2026-08-11 / 08-14 — `[OFFICIAL]`

ModelScope's own community account published a Chinese LTX-2.5 release write-up on
**2026-08-14** (`https://modelscope.csdn.net/6a7e76ba10ee7a33f29ac6c5.html`) and

Published open weights table, verbatim from the ModelScope post:

```text
| ltx-2.5-22b-dev-transformer-bf16                     | 完整模型，面向高质量流程与微调 |
| ltx-2.5-22b-distilled-transformer-bf16               | 固定 8 步蒸馏版，CFG=1 |
| ltx-2.5-22b-distilled-transformer-comfy-int8-convrot | 蒸馏版 DiT（Comfy int8 + convrot）。仅限 ComfyUI，不适用于 ltx-pipelines / PyTorch。|
| ltx-2.5-22b-dev-transformer-comfy-int8-convrot       | 完整版 DiT（Comfy int8 + convrot）。仅限 ComfyUI，不适用于 ltx-pipelines / PyTorch。|
| ltx-2.5-22b-distilled-transformer-nvfp4              | 蒸馏版 DiT（NVFP4）。适用于 ComfyUI，或在 ltx-pipelines 中配合 --quantization nvfp4-prequant 使用（Blackwell / ltx-kernels）。|
```

Concrete generation constraints stated in Chinese, `[OFFICIAL]`:

```text
省略 --num-frames 时，模型会调用 Duration Predictor 自动设置时长。手动指定时，
帧数必须满足 num_frames % 8 == 1，宽度和高度需要能被 32 整除。
```

That frame-grid rule (`num_frames % 8 == 1`, dims divisible by 32) is a hard,
checkable constraint and is the kind of thing Prompt Studio should surface. I did not
see it in the listed corpus positions.

Also `[OFFICIAL]` from these two pages, useful as depth:
- Architecture: **22B asymmetric dual-stream diffusion Transformer**, joint video+audio via bidirectional cross-attention and **modality-aware classifier-free guidance**.
- Text encoder: **Gemma 4 12B with a learnable projection** (`gemma4-12b-with-proj-ltx-2.5`).
- New **Diffusion Video Decoder** replaces the prior VAE reconstruction stage; a faster convolutional VAE also ships, user-selectable.
- Optional **Duration Head** model patch; **distilled LoRA (450)**; latent **spatial** 2× and latent **temporal** 2× upscalers ship separately.
- **Diffusion Fidelity Rendering (DFR)**: allocates render compute by scene complexity.
- Distilled model: ~6–8 s for a 10 s clip on NVIDIA superchips (vendor claim).

A **documentation inconsistency worth flagging** — `[OFFICIAL]`, and it complicates
the corpus position "LTX-2.5 ships its own spatial upscaler". In the same ModelScope
article, the **T2V** example passes the 2.5 upscaler:

```text
--spatial-upsampler-path ../LTX-2.5/latent_upscale_models/ltx-2.5-latent-spatial-upscaler-x2-bf16-1.0.safetensors
```

but the **I2V** example still passes the **2.3** upscaler:

```text
--spatial-upsampler-path models/ltx-2.3/ltx-2.3-spatial-upscaler-x2-1.1.safetensors
```

Both appear in official-derived Chinese docs on the same page. `[SPECULATION]` — this
is most likely a copy-paste carry-over in the docs rather than a real requirement, but
it means anyone following the official I2V snippet literally is running the 2.3
upscaler against 2.5 latents. Worth a Western-sweep cross-check against the English
README.

### 4.1 Wan 2.1 — official repo, verified `[OFFICIAL]`

Source: `https://github.com/Wan-Video/Wan2.1/blob/main/wan/utils/prompt_extend.py`
(accessed 2026-08-28). This file is the *verified* baseline; Wan 2.2 (§4.2) is a
transcription. Six constants exist: `LM_ZH_SYS_PROMPT`, `LM_EN_SYS_PROMPT`,
`VL_ZH_SYS_PROMPT`, `VL_EN_SYS_PROMPT`, `VL_ZH_SYS_PROMPT_FOR_MULTI_IMAGES`,
`VL_EN_SYS_PROMPT_FOR_MULTI_IMAGES`.

**Dispatch logic** (verbatim) — note the bit-packing, which determines which prompt is
used and is easy to get wrong:

```python
SYSTEM_PROMPT_TYPES = {
    int(b'000', 2): LM_EN_SYS_PROMPT,
    int(b'001', 2): LM_ZH_SYS_PROMPT,
    int(b'010', 2): VL_EN_SYS_PROMPT,
    int(b'011', 2): VL_ZH_SYS_PROMPT,
    int(b'110', 2): VL_EN_SYS_PROMPT_FOR_MULTI_IMAGES,
    int(b'111', 2): VL_ZH_SYS_PROMPT_FOR_MULTI_IMAGES
}

def decide_system_prompt(self, tar_lang="zh", multi_images_input=False):
    zh = tar_lang == "zh"
    self.is_vl |= multi_images_input
    task_type = zh + (self.is_vl << 1) + (multi_images_input << 2)
    return SYSTEM_PROMPT_TYPES[task_type]
```

`[OFFICIAL]` **The default target language is Chinese** (`tar_lang="zh"` is the
function default). An English-speaking user who enables `--use_prompt_extend` without
setting `--prompt_extend_target_lang` gets a **Chinese** rewritten prompt.

**`LM_ZH_SYS_PROMPT` (T2V), verbatim:**

```text
你是一位Prompt优化师，旨在将用户输入改写为优质Prompt，使其更完整、更具表现力，同时不改变原意。
任务要求：
1. 对于过于简短的用户输入，在不改变原意前提下，合理推断并补充细节，使得画面更加完整好看；
2. 完善用户描述中出现的主体特征（如外貌、表情，数量、种族、姿态等）、画面风格、空间关系、镜头景别；
3. 整体中文输出，保留引号、书名号中原文以及重要的输入信息，不要改写；
4. Prompt应匹配符合用户意图且精准细分的风格描述。如果用户未指定，则根据画面选择最恰当的风格，或使用纪实摄影风格。如果用户未指定，除非画面非常适合，否则不要使用插画风格。如果用户指定插画风格，则生成插画风格；
```

**Structural finding first.** The file has **two** full system prompts and routes
